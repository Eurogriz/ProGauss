# ADR-002. Референсное NumPy-ядро остаётся в продукте навсегда

**Статус:** принято · **Дата:** 2026-08-26

## Контекст
Оптимизации в квантовой химии легко меняют физику незаметно: пропущенный член
в рекурсии, другой порядок суммирования, иная сетка. Обнаружить это по
«разумным на вид» числам невозможно.

## Решение
Первой реализуется **референсная** реализация (NumPy, один поток, плотные
массивы, без скрининга). Она остаётся в продукте как backend `reference-cpu`
и как арбитр в тесте эквивалентности L10 для всех оптимизированных backend'ов.

## Альтернативы
- **Сразу писать оптимизированное ядро** — нечем верифицировать; ошибки
  находятся пользователями.
- **Референс только в тестах** — он устаревает и перестаёт собираться.

## Последствия
- Двойная поддержка двух реализаций (принимается: референс мал и стабилен);
- Допуск эквивалентности 1e-8 Eh зафиксирован в верификации;
- Референс медленный в 50–200 раз и никогда не используется в production-профиле.
