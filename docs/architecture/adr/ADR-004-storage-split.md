# ADR-004. Метаданные в SQL, научные массивы в object storage

**Статус:** принято · **Дата:** 2026-08-26

## Контекст
Гессиан на 500 атомов — это ~1 МБ на расчёт, кубические сетки плотности —
десятки МБ. Хранение таких значений в SQL ломает индексы, бекапы и репликацию.

## Решение
- PostgreSQL: задания, статусы, события, скаляры результатов, проверки качества;
- S3-совместимое хранилище: градиенты, гессианы, орбитали, плотности, ESP,
  отчёты — с content-addressed ключами и `sha256`;
- Redis: прогресс, блокировки, кэш;
- частоты (десятки чисел) остаются в SQL — ими удобно запрашивать и экспортировать.

## Альтернативы
- **Всё в SQL** — деградация БД на масштабе;
- **Всё в файлах** — нет транзакций для статусов и аудита;
- **Документная БД как основная** — нет нужной строгости для состояний.

## Последствия
- Двухфазная запись (артефакт → ссылка в SQL) требует аккуратности: сначала
  пишем артефакт, потом ссылку; обратный порядок оставляет «висящие» файлы;
- Чтение проверяет `sha256`;
- Подписанные URL для скачивания, чтобы API не проксировал гигабайты.
