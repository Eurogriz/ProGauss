# ADR-003. Реестр возможностей как единственный источник правды

**Статус:** принято · **Дата:** 2026-08-26

## Контекст
ТЗ (§54) запрещает выдавать нереализованный метод за работающий. На практике
GUI и ядро расходятся: интерфейс показывает метод, которого в движке нет, и
пользователь получает фиктивные результаты.

## Решение
Каждая возможность (метод, функционал, базис, задача, формат, backend,
планировщик) — запись `Capability` со статусом
`implemented | partial | not_implemented`. GUI, CLI и API спрашивают у реестра.
Смена статуса на `implemented` допускается только вместе с верификационными
кейсами.

## Альтернативы
- **Список методов в коде UI** — расходится с ядром в первый же релиз.
- **Определять доступность по наличию класса** — не описывает частичную
  реализацию и ограничения.

## Последствия
- Плагины регистрируют такие же записи — единый механизм расширения;
- Раздел «База методов» в GUI строится из снимка реестра;
- Реестр версионируется вместе с API.
