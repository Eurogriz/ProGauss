# ADR-005. Собственный scheduler на PostgreSQL вместо готовой очереди

**Статус:** принято · **Дата:** 2026-08-26

## Контекст
Нужны: приоритеты по проектам, вытесняющая отмена, рестарт с чекпоинта,
идемпотентные повторы, HPC-планировщики как исполнители и полная наблюдаемость
состояния.

## Решение
Очередь — таблица `jobs` с частичным индексом по `status = 'queued'` и выборкой
через `FOR UPDATE SKIP LOCKED`. Исполнители подключаются через
`SchedulerAdapter` (local, slurm, pbs, lsf, kubernetes).

## Альтернативы
- **Celery/RQ** — удобны для коротких задач, но состояние задачи живёт вне БД,
  а семантика приоритетов и отмены ограничена;
- **Внешний брокер (RabbitMQ/Kafka)** — ещё один компонент для обслуживания
  и ещё одно место, где состояние может разойтись с БД.

## Последствия
- Очередь ограничена производительностью PostgreSQL (десятки тысяч заданий в
  секунду — более чем достаточно);
- Вся логика очередей видна в SQL и покрыта тестами;
- Переход на внешний брокер возможен, если станет узким местом: интерфейс
  планировщика это изолирует.
