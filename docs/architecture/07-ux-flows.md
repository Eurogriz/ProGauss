# 07. UX: интерфейс, мастер расчёта, локализация, ошибки

## 7.1 Каркас интерфейса (§16 ТЗ)

```text
┌──────────────┬──────────────────────────────────────┬───────────────────┐
│ Левое меню   │ Рабочая область                       │ Панель результатов │
│              │                                       │                   │
│ Проекты      │  ┌─────────────────────────────────┐  │ Итог расчёта       │
│ Молекулы     │  │                                 │  │  Энергия           │
│ Расчёты      │  │   Молекулярный редактор /        │  │  HOMO / LUMO / Gap │
│ Очередь      │  │   форма расчёта / таблица        │  │  Диполь            │
│ Результаты   │  │                                 │  │  Время             │
│ Визуализация │  └─────────────────────────────────┘  │  [Показать         │
│ HPC          │                                       │   подробный расчёт]│
│ Настройки    │  Прогресс · Журнал · Ошибки            │  Проверки качества │
│ База методов │                                       │  Рекомендации      │
│ Справка      │                                       │                   │
└──────────────┴──────────────────────────────────────┴───────────────────┘
```

Главная страница — сводка: последние проекты, активные расчёты, ошибки,
завершённые задачи, используемые ресурсы. Никаких «пустых экранов настроек» на
входе: первый экран предлагает **создать молекулу** или **открыть мастер**.

## 7.2 Основной сценарий (§2 ТЗ)

```text
Создать молекулу → выбрать тип расчёта → выбрать точность → нажать «Рассчитать»
```

Полный путь пользователя — 6 шагов мастера (§17 ТЗ):

| Шаг | Что делает пользователь | Что делает система |
|---|---|---|
| 1. Молекула | Рисует, импортирует файл/SMILES или берёт из библиотеки | Проверяет валентности, находит подозрительные контакты, строит 3D, предлагает корректную мультиплетность |
| 2. Задача | Выбирает: Энергия / Оптимизация / Частоты / ТС / Сканирование / Свойства | Показывает описание задачи на человеческом языке |
| 3. Метод | Выбирает: Быстро / Стандарт / Высокая точность / Эксперт | Разворачивает профиль в полную спецификацию и **показывает каждое решение с обоснованием** |
| 4. Ресурсы | Обычно ничего не делает | Предлагает CPU/RAM/GPU/потоки с объяснением оценки |
| 5. Проверка | Читает сводку | Показывает: что считаем, каким методом, сколько это займёт, что будет на выходе |
| 6. Запуск | Нажимает **«Рассчитать»** | Создаёт задание, ставит в очередь, открывает страницу прогресса |

Экран «Метод» — ключевой. Он выглядит не как список параметров, а как четыре
карточки с ценой и точностью:

```text
┌─ Быстрый скрининг ─────────┐  ┌─ Стандартный расчёт ───────┐
│ PBE/def2-SVP + D3(BJ)      │  │ PBE0/def2-SVP + D3(BJ)     │
│ ~минуты                    │  │ ~десятки минут             │
│ Для оценки многих структур │  │ Для большинства задач      │
└────────────────────────────┘  └────────────────────────────┘
┌─ Высокая точность ─────────┐  ┌─ Исследовательский ────────┐
│ PBE0/def2-TZVP + D3(BJ)    │  │ ωB97X-D/def2-TZVP          │
│ ~часы                      │  │ ~часы и больше             │
│ Для публикуемых значений   │  │ Полный контроль            │
└────────────────────────────┘  └────────────────────────────┘
                    [ Расширенные настройки ]
```

Выбор сопровождается объяснением (§8 ТЗ):

> **Потому что выбран профиль «Высокая точность»**
> · Выбран функционал pbe0
> · Выбран базисный набор def2-tzvp
> · Дисперсионная поправка: d3bj
> · Квадратурная сетка: ultrafine
> · Порог сходимости SCF: 1e-09
> · Число потоков: 8 · Память на расчёт: 4096 МБ — оценка по 240 базисным функциям

Эти строки генерирует `resolve_profile(...).explain(locale)` — тот же код,
который вызывается из CLI (`quantumlab plan`) и из `POST /calculations/plan`.

## 7.3 Три уровня пользователя (§46 ТЗ)

| Уровень | Что видно | Переключение |
|---|---|---|
| **Новичок** | Задача + 4 профиля точности. Всё остальное подобрано автоматически | по умолчанию |
| **Исследователь** | Раскрытые «Расширенные настройки»: базис, функционал, дисперсия, сетка, критерии оптимизации, ресурсы | кнопка «Расширенные настройки» |
| **Эксперт** | Сырой input, все пороги SCF и интегралов, сетки, память, окружение, пользовательский базис/функционал, параметры рестарта | «Экспертный режим» в настройках |

Один backend обслуживает все три режима: эксперт просто заполняет те же поля
`CalculationSpec`, которые для новичка заполнил автоподбор. Никакого
«отдельного кода для экспертного пути».

## 7.4 Объяснимость (§18 ТЗ)

У каждого сложного параметра — подсказка из четырёх частей. Структура
ключей: `tooltip.<параметр>.{title,what,why,if_changed,relevant_for}`;
полнота проверяется тестом `test_explainability_tooltips_are_complete`.

Пример для мультиплетности (рус. каталог):

> **Мультиплетность**
> **Что это?** Число, связанное с суммарным спином электронной системы: 2S+1.
> Для замкнутых оболочек обычно выбирается «Синглет» (1).
> **Зачем это?** Задаёт распределение электронов по спинам и определяет,
> открытая или закрытая оболочка у системы.
> **Что произойдёт, если изменить?** Неверное значение приводит к другому
> электронному состоянию — энергия и геометрия будут относиться не к той системе.
> **Для каких систем это важно?** Радикалы, триплетные состояния, комплексы
> переходных металлов, диссоциирующие связи.

Покрыты: заряд, мультиплетность, функционал, базис, дисперсия, сетка, порог
SCF, порог отсечки интегралов, потоки, память, устройство.

## 7.5 Ошибки как сценарий, а не как текст (§19 ТЗ)

Карточка ошибки в UI:

```text
⚠ Расчёт не завершён
  Электронная структура не достигла требуемой сходимости

  Что произошло
  Система пыталась найти устойчивое электронное состояние, но итерационный
  процесс не сошёлся за 80 итераций (остаточная ошибка 3.100e-05).
  Такое поведение характерно для систем с близкими по энергии орбиталями:
  радикалов, переходных металлов, возбуждённых состояний.

  Что мы попробовали
  • DIIS-ускорение  • затухание (damping)  • сдвиг уровней (level shifting)

  Что можно сделать
  [ Повторить автоматически ]  [ Использовать более устойчивый алгоритм SCF ]
  [ Изменить настройки вручную ]
```

Все три блока и список кнопок приходят из объекта ошибки
(`DiagnosisError.explain()` / поля `tried` и `actions` в `Problem`), поэтому
текст всегда описывает реальные действия движка. Список «Что мы попробовали»
берётся из `ScfResult.strategies_used` — движок не может заявить стратегию,
которую не применил.

## 7.6 Рекомендации после расчёта (§29 ТЗ)

| Наблюдение | Рекомендация | Кнопки |
|---|---|---|
| Одна мнимая частота | «Структура похожа на переходное состояние» | Найти структуру переходного состояния · Показать нормальную моду |
| Несколько мнимых частот | «Геометрия не сошлась в минимум» | Оптимизировать заново · Показать нормальную моду |
| SCF занял > 60 итераций | «Рекомендуется более устойчивая SCF-схема» | Перезапустить автоматически · Изменить настройки |
| Задание упало по памяти | «Не хватило оперативной памяти» | Увеличить объём памяти · Включить direct SCF |
| Расчёт прерван | «Есть контрольная точка» | Продолжить расчёт |

## 7.8 Локализация (§3 ТЗ)

- Русский — язык по умолчанию; английский — обязательный второй язык.
- Переключатель «Русский / English» в настройках; выбор сохраняется в профиле
  пользователя.
- В коде **нет UI-строк**, только ключи. На текущем коммите: **311 ключей**,
  паритет ru/en проверяется тестом `test_locales_have_identical_key_sets`,
  совпадение плейсхолдеров — `test_placeholders_match_across_locales`.
- Подстановка только именованными параметрами (`{value}`), конкатенация строк
  запрещена: порядок слов в русском и английском разный.
- Локализуется всё: меню, кнопки, подсказки, статусы, ошибки, журнал, отчёты,
  справка, wizard.

## 7.9 Производительность GUI (§30 ТЗ)

- Любая операция дольше 200 мс выполняется асинхронно и показывает состояние:
  импорт файлов, построение поверхностей, рендер крупных систем.
- Прогресс расчёта приходит по SSE (`GET /jobs/{id}/events`), а не опросом
  таймером; UI не блокируется и не «дёргается».
- Изоповерхности считаются на worker'е (марширующие кубы), в браузер приходит
  геометрия, а не сетка: это десятки МБ против единиц.
- Визуализация — инстансинг и frustum culling; целевая плавность 60 fps при
  10⁴ атомов.

## 7.10 Доступность (§35 ТЗ)

- Полная навигация с клавиатуры, видимый фокус, логичный порядок табов,
  фокус-ловушки в модальных окнах.
- Контраст текста ≥ 4.5:1, светлая и тёмная темы, шрифт не меньше 14 px,
  масштабирование интерфейса без поломки раскладки.
- Статусы дублируются не только цветом: у каждой ошибки — иконка и текст.
- Адаптивная раскладка: панель результатов сворачивается, меню — в гамбургер.
- Правило «20/80»: на экране — только 20 % самых важных настроек, остальное
  в «Расширенных».
